# 学程第三阶段｜前后端闭环执行清单

此文档是本阶段的团队交接清单。每个步骤都先写清楚数据归属、完成条件和下一步，避免页面、数据层和 API 各自实现一套状态。

## 0. 工作边界

- 基线：`56e0687`。
- 不改 Pixso 视觉，不上传模型 Key、原始录音、附件、二进制头像、资料原文或诊断日志。
- 浏览器保持本地优先；任何远端写入都应由登录后的用户操作触发。

## 1. 身份与本地账户作用域

**负责人：前端数据层**

- [x] 从公开 OIDC 配置读取授权端点、Token 端点、客户端 ID 和回调地址。
- [x] 使用授权码 + PKCE 建立真实登录跳转；不能配置时显示“未配置”，不得伪造账户。
- [x] Access Token 仅驻留内存；刷新后需要重新认证。仅把一次性 PKCE 事务写入会话存储。
- [x] 按已验证会话的 `issuer + subject` 切换本地数据作用域；切换账号前后不得显示另一账号的数据。

**完成条件：** 未登录不请求私人 API；401 进入重新认证；403 与 503 呈现不同错误状态。

## 2. 统一 Repository

**负责人：前端数据层**

- [x] 页面只调用 Repository，不直接调用应用 API。
- [x] Repository 统一管理本地状态、远端版本（ETag）、同步状态与可恢复错误。
- [x] 首页启动时先展示本地快照，再尝试读取远端安全投影；本地有未同步改动时禁止静默覆盖。

**完成条件：** 首页、对话、日程、我的四个模块只有一个远端访问入口。

## 3. 四个模块闭环

**负责人：前端页面逻辑 + API 契约维护**

- [x] 首页：真实 `GET/PUT /api/v1/home`，Next Step 来自保存的 Agent 状态。
- [x] 对话：本地立即显示、同一 `client_message_id` 重试幂等、分页读取历史；只上传用户确认的文字。
- [x] 日程：建议保持 pending；确认调用原子确认接口，手动日程走创建/修改接口；冲突不覆盖。
- [x] 我的：资料、主题、陪伴者与安静时段先本地更新；服务器拒绝时回退，网络失败时保留本地待同步状态。

**完成条件：** 日程建议不会未经确认写入正式日程；消息和设置在网络恢复后的显式同步中可恢复。

## 4. 显式同步中心

**负责人：我的页面**

- [x] 在“我的”提供唯一的同步入口，显示：需要登录、同步中、已同步、同步失败、冲突待处理。
- [x] 仅用户点击后发送可同步字段；显示最近一次成功同步时间。
- [x] 历史本地数据迁移必须另行获得用户确认，本阶段不自动批量上传。

**完成条件：** 无登录、断网、冲突和服务未配置都不会损失本地数据或触发后台上传。

## 5. 验证与交接

**负责人：测试**

- [x] 增加 Repository/认证单元测试和浏览器端到端流程。
- [x] 覆盖游客持久化、登录同步、断网、本地恢复、账号切换、消息幂等、日程确认与敏感字段排除。
- [ ] 运行 `npm run test:api`、`npm test`、移动包 QA 与交付 QA。（下一步：完成最终改动后重跑四组完整验证。）

**完成条件：** 测试报告明确区分已编码、已测试、已部署、已真机验证。

## 部署接入注释（下一位同事从这里开始）

在托管页面加载 `iphone.js` **之前**，由部署层注入以下公开配置；只能提供客户端 ID，绝不能写入 OIDC client secret、模型 Key 或用户 token：

```js
window.__XUECHENG_API_BASE__ = "https://api.example.com";
window.__XUECHENG_OIDC_CONFIG__ = {
  authorizationEndpoint: "https://identity.example.com/authorize",
  tokenEndpoint: "https://identity.example.com/oauth/token",
  clientId: "xuecheng-web-public-client",
  redirectUri: "https://app.example.com/",
  issuer: "https://identity.example.com",
  scope: "openid profile"
};
```

**部署完成后下一步：** 先在预发布环境验证回调 URI、CORS 和 RS256 JWKS，再用两个真实测试账号检查账户切换隔离；未完成这些步骤前，产品会如实显示“登录服务尚未配置”，不会伪造登录或上传本地数据。
