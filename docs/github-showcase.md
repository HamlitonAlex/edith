# GitHub 展示与首发方案

## 一句话定位

学程不是生成一份人生计划的聊天机器人，而是一位会长期了解你、主动联系你，并把建议落实到今天具体时间与现实入口里的私人教育伙伴。

## 首页前三屏

1. **先看到产品，而不是概念**：首屏展示 iPhone 对话、具体任务卡片与一句定位，按钮只保留“在线体验”和“本地运行”。
2. **用一个真实闭环解释差异**：用户随口说近况 → 伙伴形成判断 → 提出一项具体安排 → 到时间主动询问 → 记录真实变化。
3. **坦诚展示当前能力**：把已完成、可演示、规划中分开，避免把日历、微信、抖音等尚未接通的来源包装成可用功能。

## 最值得传播的演示

录制一段 45–60 秒竖屏视频：

- 0–8 秒：伙伴主动找用户聊天；
- 8–20 秒：用户按住说一句模糊近况；
- 20–35 秒：伙伴把它变成包含时间、平台、内容和完成标准的安排；
- 35–48 秒：切到“今天”和“路径”，展示短期行动如何沉淀为长期方向；
- 48–60 秒：展示主题与伙伴形象可自定义，并出现在线体验与 GitHub 地址。

不要用功能列表做主视频。GitHub 访客需要先在一分钟内理解“它替我改变了什么”。

## 仓库信任结构

- README：结果、动图、在线体验、三分钟启动；
- `PRODUCT.md`：产品边界和核心判断；
- `docs/iphone-first-product-direction.md`：为什么优先 iPhone；
- `docs/integrations/event-ingestion.md`：数据接入原则；
- Issues：公开标注 `good first issue`、`help wanted`、`design`；
- Releases：Web 演示稳定后发布 `v0.1.0-preview`，附 IPA 的用途与自签说明。

## 获得 Star 的合理路径

1. 先做到“点开即懂、在线即玩、三分钟能跑”。
2. 用演示视频讲一个具体生活变化，而不是宣传“全能 AI”。
3. 首发前准备 5–8 个边界清楚的贡献任务，让新贡献者当天能提交改进。
4. 在开发者社区分享设计取舍、iOS 键盘坑和主动式助手安全边界，提供可复用经验。
5. 不购买 Star、不批量私信、不夸大连接器能力；长期信任比一次榜单峰值重要。

## 首发验收标准

- 在线演示无需登录且核心交互可用；
- README 首屏在手机和桌面都能看懂；
- iPhone 竖屏视频低于 60 秒；
- `npm ci && npm test && npm run build:web` 可以复现；
- 未签名 IPA 能从 Codemagic 构建产物下载，并明确需要用户自行签名；
- 至少 5 个适合外部贡献者的 Issues 已准备，但不要在功能尚未验证前一次性公开过多承诺。
