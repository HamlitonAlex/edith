# 生活学习事件原型设计

## Summary

构建一个零依赖、可本地运行的网页原型，演示日历计划、课程行为、语音自述、作品证据和系统推测如何进入同一时间线。用户能查看每条信息为什么被系统知道、确认或否定推测，并预览由条件变化引起的学习方案调整。

这个里程碑使用虚构数据，不申请系统权限、不连接个人账户、不上传真实信息。它验证产品的核心理解方式和传播叙事，并为 Android、Apple Shortcuts 和未来 iOS 伴生端定义统一事件协议。

## Chosen approach

使用浏览器原生 HTML、CSS、JavaScript 和 Node.js 内置测试工具。当前目录没有代码项目，npm 安装损坏，但 Node 和 pnpm 可用；零依赖方案可以立即运行，也避免在产品行为尚未验证时引入框架复杂度。

网页包含家庭英语与成人数据分析两个场景。每个场景展示当天事件、来源、信息类型、确认状态、学习地图摘要和调整建议。交互状态保存在浏览器本地，提供重置演示按钮。

## Components

- `packages/event-schema`：事件类型、字段校验、可见性、确认状态和方案调整协议。
- `apps/web`：公开演示和可操作时间线。
- `examples/events`：Android、Apple Shortcuts 和通用连接器的示例请求。
- `docs/integrations`：采集端接入同一事件接口的说明。
- `scripts/serve.mjs`：本地静态服务，不依赖第三方包。

## Data flow

虚构数据载入浏览器后先经过事件校验，再按发生时间排序。界面只把计划、行为、自述和作品呈现为来源事实；系统推测保持待确认。用户确认或否定后，本地状态更新并记录决定。调整卡根据场景中的条件变化展示受影响的行动、保留内容和原因，只有用户采用后才显示为当前方案版本。

## Error handling

无效事件不会加入时间线，界面显示具体字段错误。浏览器存储不可用时退化为当前会话状态。未知事件类型以安全的通用标签显示。静态服务限制文件访问在项目目录内，拒绝路径穿越。

## Verification

使用 Node 内置测试验证事件校验、排序、推测确认、调整采用和路径限制。人工检查两个场景、窄屏布局、键盘操作、详情展开和重置演示。

## Open risks

本里程碑不验证手机系统真实采集、模型推理质量、教育效果和连接器权限。Android 原生端与 Apple Shortcuts 在下一里程碑接入；当前只冻结事件协议和样例。



## 2026-09-06 修订：日常入口优先

用户指出：即使系统具备完整时间线和方案能力，只要仍要求人先打开复杂工作台、判断记录类型或学习固定说法，日常使用成本就仍然过高。因此首屏从“解释系统”改为“直接接住一句自然表达”。

日常交互遵循四条规则：

1. 用户按平时方式说话，不需要命令、标签或分类。
2. 系统先保存带来源的候选事件，不因一句话立即修改长期方案。
3. 家长对孩子的描述保留为家长观察，不替孩子形成结论。
4. 没有重要变化时保持安静；只有推测和方案决策才请求确认，单次最多呈现一个决定。

时间线、来源解释和方案版本继续保留，但下沉为“想深入时再看”的审计层。网页语音按钮只是入口验证；真正融入生活仍需 Android 系统分享、快捷语音和连接器，不能把打开网页当作最终形态。
